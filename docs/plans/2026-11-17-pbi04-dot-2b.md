## B2. Migration

- Tên theo quy ước hiện có: `V2026111[78]hhmm__<mô tả>.sql` trong `db/migration/<schema>`. Mỗi lane lấy giờ phút của lúc tạo tệp.
- Trùng phiên bản thì lane sau đổi số khi rebase.
- **Chuyển dữ liệu cấu trúc** (2B mục 3.5) là migration Java (`BaseJavaMigration`), vì phải sửa `jsonb` theo luật.
  - Repo chưa có migration Java. Flyway chỉ quét `classpath:db/migration` (`application.yml`), nên lớp đặt ở `backend/src/main/java/db/migration/`, package `db.migration`, tên `V2026111[78]hhmm__ExamStructureV2.java`. Không đặt trong package của module `exam`: Flyway sẽ không thấy.
  - Lớp chỉ dùng JDBC và Jackson. Kiểu cũ được sao chép vào package con `db.migration.examv1`, không dùng kiểu domain đang chạy. Kiểm tra ArchUnit, Modulith có chặn package này không; chặn thì báo Advisor.
  - Có test riêng với tệp đầu vào và tệp mong đợi.
- **Thứ tự chạy:** migration `V…` chạy trước tệp `R__` trong `db/devdata`. Trên DB mới (Testcontainers, dev mới), migration chuyển dữ liệu chạy lúc bảng còn trống, rồi `R__` chèn dữ liệu mẫu. Vì vậy tệp `R__` có cấu trúc đề thi phải được viết lại theo dạng mới **trong cùng PR** với migration (BE-1).
- **Mẫu (BE-7)** nạp bằng migration SQL `UPDATE exam.exam_template … WHERE code = …` như `V202611171200`.
  - Mẫu mới thì `INSERT … ON CONFLICT (code) DO UPDATE`.
  - JSON của mẫu dựng bằng một script trong `backend/src/test/resources/templates/` và kiểm bằng test, không viết tay một dòng dài.

## B3. Bộ giải

- `PaperSolver` giữ một thuật toán cho kiểm tra, sinh thử và sinh đề thật (BE D15).
- Mọi luật riêng của kỳ thi nằm trong dữ liệu mẫu hoặc trong một hàm riêng: `ChoiceGroupAllocator`, `TrimPolicy`. Không viết `if (kind == HSA)` trong bộ giải.
- `PaperOrdering` là hàm thuần, không đọc DB. Nó nằm ở `exam/spi` để module `attempt` của đợt 3 dùng lại.
